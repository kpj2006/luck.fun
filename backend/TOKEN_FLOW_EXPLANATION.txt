# RUGS.FUN Token Flow & Accounting Architecture (Authoritative)

## Core Principles
1. **Solvency Invariant**: At all times, the Contract's physical ERC20 balance MUST be greater than or equal to the sum of all internal user balances (`balances[user]`).
2. **Net Profit Only**: Only the platform's net profit (Losing Bets - Winning Payouts) should ever move to the Treasury. User principal must remain in the contract pool to back withdrawals.

## Phase Breakdown

### 1. Deposit (Physical Move)
*   **Action**: User Wallet ➔ RugsFun Contract.
*   **Mechanism**: Standard ERC20 `transferFrom`.
*   **Result**: 
    *   Wallet balance decreases.
    *   Contract address holds the physical tokens.
    *   `balances[user]` (internal ledger) increases.

### 2. Gameplay (Internal Accounting)
*   **Action**: Buy / Win / Loss.
*   **Mechanism**: Simple variable updates in the contract/Supabase ledger.
*   **Result**: 
    *   **Buy**: `balances[user] -= bet`. The bet is now platform-controlled liquidity.
    *   **Win**: `balances[user] += payout`.
    *   **Loss**: No action (bet was already deducted at Buy).
    *   **NO physical ERC20 transfers** occur during ticks to preserve speed and minimize gas.

### 3. End Game & Settlement (Economic Finality)
*   **Action**: Finalizing the platform's cut.
*   **Mechanism**: Calculate `Total Losers - Total Winners`.
*   **Result**: 
    *   If Winners > Losers: The contract uses its accumulated "Safety Buffer" or surplus to pay out.
    *   If Losers > Winners: The **surplus (Net Profit)** is eligible for transfer to the Treasury.
    *   **CRITICAL**: Do NOT transfer all tokens to the treasury after a game. Only move the surplus profit.

### 4. Platform Payout (Surplus Sweep)
*   **Action**: Contract ➔ Treasury.
*   **Frequency**: Deferred (Daily/Weekly) or manual sweep.
*   **Mechanism**: `transfer(treasury, contractBalance - sumUserBalances)`.
*   *This ensures the contract never becomes insolvent.*

### 5. Withdrawal (Physical Move)
*   **Action**: RugsFun Contract ➔ User Wallet.
*   **Mechanism**: Standard ERC20 `transfer`.
*   **Result**: Physical tokens leave the contract pool and return to the user's personal control.

## Accounting Table

| Action            | Physical Move? | Internal Ledger? | Flow Direction                 |
|-------------------|----------------|------------------|--------------------------------|
| **Deposit**       | YES            | YES              | User Wallet ➔ Contract Pool    |
| **Buy / Bet**     | NO             | YES              | User Balance ➔ Pool Liquidity  |
| **Win**           | NO             | YES              | Pool Liquidity ➔ User Balance  |
| **Loss**          | NO             | NO               | (Already in Pool Liquidity)    |
| **Treasury Sweep**| YES            | NO               | Contract Pool ➔ Treasury Wallet |
| **Withdrawal**    | YES            | YES              | Contract Pool ➔ User Wallet    |
